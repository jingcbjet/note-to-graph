# 设计说明

记录几个关键决策背后的理由。想改代码前建议先读这里，避免把踩过的坑再踩一遍。

## 决策一：为什么不让 LLM 全包

最直觉的做法是把一段讲义丢给模型，让它直接输出「节点 + 边 + 权重」。实践中
这条路有三个问题：

1. **慢**。模型要在一个响应里做完切分、识别概念、两两判断关联、打分，输出
   极长，单章 3–4 分钟。
2. **关联判断不一致**。同一对概念，换一次提问或换个顺序，模型给的相似度
   可能从 0.9 变成 0.4。跨章比较就失去意义了。
3. **切分不可复现**。块边界每次不一样，同一个概念在两讲里被切到不同块，
   下游合并时对不上。

所以把职责拆成三层，各自用最合适的工具：

| 职责 | 工具 | 理由 |
|---|---|---|
| 切分 | markdown 标题规则 | 有确定答案，本地做零成本且可复现 |
| 认概念 | LLM | 真的需要语义理解，无法本地替代 |
| 连边 | bge embedding + 余弦 | 数值稳定、可复现、免费、GPU 上极快 |

省下来的不只是钱。**改渲染逻辑不用重跑模型**这件事带来的迭代速度提升，
比省 token 更有价值。

## 决策二：为什么切分要"修两头"

`split_blocks` 先按标题切，然后处理两种极端：

- **太碎的块并入前块**。讲义里常见这种结构：

  ```markdown
  ## 增能理论
  （一整段正文）

  ## 增能层级
  个人层面、人际层面、社会层面。
  ```

  第二个标题下只有一行，单独送模型会让它输出一个信息量很低的节点。
  长度小于 `min_merge` 就并掉。

- **太大的块按空行二切**。有些讲义整讲都没有子标题，一个块几千字。
  超过 `max_cap` 就按空行累积切分，避免超出模型有效上下文导致漏掉后半段。

## 决策三：边必须剪枝，而且门槛要自适应

这是踩坑最多的一块，值得完整记录。

### 第一层：必须限数量

`min_sim=0.60` 且不限制数量时，26 个节点的图能连出 266 条边（8.5 条/节点），
视觉上是一团毛线，也没有信息量。加 `top_k=3` 之后同样数据是 56 条边，结构清晰。

### 第二层：固定门槛在不同讲次之间失效

上线后在一个小样本上发现密度只有 0.86 边/节点，但同样的配置在 52 讲的真实语料
上是 2.05。查下去发现根因：

**bge 的余弦相似度分布在不同讲次之间差异极大。**

同一批 52 讲语料里抽样测：

| 讲次 | 节点 | 相似度中位数 | 固定 0.60 下的密度 |
|---|---|---|---|
| 第 17 讲 | 26 | 0.691 | 10.73 边/节点 |
| 第 31 讲 | 23 | 0.511 | 2.57 边/节点 |
| 第 5 讲 | 52 | 0.493 | 6.37 边/节点 |

内容密集、术语高度相关的讲次（比如整讲都在讲同一套制度的几个侧面）相似度整体
偏高；而跨度大的讲次（一讲涵盖好几种理论）相似度整体偏低。用一个固定阈值，
等于对不同讲次施加了完全不同的标准。

解法是自适应：先用配置的门槛算一遍，如果实际密度明显偏离目标区间，就按需要的
密度反推一个分位数门槛。效果：

```
固定门槛 0.60  →  单讲密度 0.65 ~ 10.73
自适应门槛     →  单讲密度 1.40 ~ 1.93   （52 讲全科 1.71）
```

### 第三层：度数要单独封顶

`top_k` 限制的是"每个节点向外发几条边"，但边是**无向去重**的。一个节点会从
很多邻居那里被动收到边，所以实际度数可以是 `top_k` 的好几倍——实测真实语料里
出现过**度数 14** 的节点（`top_k=3` 的 4.7 倍），它在图上会拽着周围一圈节点，
整个布局被带歪。

加了一层贪心封顶：按边强度从高到低保留，直到所有节点度数不超过 `2*top_k`。
为什么不封在 `top_k`？试过，密度会被压到 1.07 边/节点，低于健康区间——
因为"向外发 3 条"和"总度数 3 条"这两件事的语义不同，强行等同会过度剪枝。

**边密度是判断图是否可读的最好指标**，健康区间 1.4–2.2 边/节点。
`ntg check` 会直接报出来。

## 决策四：跨科门槛为什么更高

科内用 0.60，跨科用 0.82。不对称是刻意的：

- 科内连错一条边，只是图上多了条多余的线，用户能自己忽略
- 跨科连错一条边，用户会以为两个领域间存在某种对应关系，可能建立**错误的类比**

后者的代价高得多，所以宁可漏连也不要错连。实测 0.82 下产出的边质量不错，
例如「非理性信念辩论技巧」（0.957）、「枫桥经验」（0.864）这类确实是真的同源概念。

## 决策五：多科目合并的 id / lecture 处理

把多张图放进同一个 ECharts 实例时，两处会撞车：

1. **节点 id**。每张图都从 0 开始编号，合并后大量重复。必须先算全局偏移量
   顺延，边同步 remap。
2. **讲次号**。科目甲的「第 1 讲」和科目乙的「第 1 讲」不是一回事。
   用 `科目序号 * 1000 + 讲号` 全局化，前端 `g % 1000` 还原出局部讲号显示。

`*1000` 而不是别的数，是因为单个科目的讲数不会到 1000，这样既能保证唯一，
又能一眼看出科目归属。

## 决策六：Obsidian 概念词条为什么要白名单

第一版给全部 3704 个概念每个建一个文件，结果是：

- 库里有 3704 个文件，检索和浏览都瘫痪
- 大量概念只出现过一次、没有任何关联，单独一个文件没有价值
- 讲次笔记里引用了没建词条的概念，产生成片灰色空链接

改成白名单后收敛到 966 个：

- **跨科目或跨讲出现** → 天然是知识枢纽，值得独立成页
- **重要度 5 且科内度数 ≥3 且标签 ≥4 字** → 考点中心，且标签足够具体
- **额外剔除模板噪音**（「本讲速记要点」「本章小结」这类）——它们被模型
  当成了概念，实际是讲义的脚手架

没入选的概念**仍然完整保留在讲次笔记里**，只是不单独建页。
`ref()` 辅助函数保证只有目标文件存在时才写 `[[双链]]`，从源头杜绝灰色链接。

## 决策七：缓存粒度选在"讲"

缓存写在 `output/cache/nodes_<tag>_L<num>.json`，每讲一个文件。

不选整图一个缓存文件的原因：一讲失败会污染整个缓存，重跑要重头来。
按讲分文件后，删掉对应文件就能单独重做，其余讲次零成本。

这也是为什么 LLM 阶段和算边阶段是分开的两趟：LLM 慢而贵，embedding 快而免费，
分开后重跑边逻辑完全不用碰模型。

## 已知限制

- **只支持 OpenAI 兼容接口**。要接别家协议得在 `llm.py` 里加适配。
- **embedding 模型是中文优先的**。处理英文语料建议换成 `BAAI/bge-large-en-v1.5`
  或 `all-MiniLM-L6-v2`。
- **概念去重靠标签精确匹配**。模型把同一概念写成「增能理论」和「增能理论框架」
  时会被当成两个。这是当前最大的质量问题来源，彻底解决需要一次概念归并
  的 LLM 调用（又是一轮成本，暂未做）。
- **白名单阈值是经验值**。不同语料的合适阈值不同，可能需要根据实际产出调整
  `obsidian.py` 里的 `_pick_concepts`。
